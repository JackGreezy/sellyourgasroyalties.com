# Sell Gas Royalties project rules

- This project is a faithful, multi-page relabel of `nanoavionics.com`. Preserve the donor DOM, black editorial hero, tall image cadence, reliability/process bands, mission-needs grid, product index, technical detail hierarchy, blue contact panel, typography, navigation behavior, and page-family distinctions.
- The homepage hero must contain exactly one visible, nonempty, SEO-driven H1 naming gas royalties and Pittsburgh, Pennsylvania. A blank hero image is a release-blocking defect.
- This is a business website, never a personal blog. Singular first-person editorial language (`I`, `me`, `my`, `myself`) is forbidden in authored and rendered copy, including FAQ questions and consent text.
- The writing belongs only to `sellyourgasroyalties.com`: a Pittsburgh gas-royalty underwriting desk organized around a five-line netback ledger—title, decimal, well, netback, and transfer. It distinguishes dry gas, wet gas, NGL revenue, basis differentials, gathering, compression, processing, decline, title, and deed terms. Never copy this voice into another domain, a shared pack, or a reusable template.
- Use only the mapped local image inventory in `images/` and its staged `public/ours/` copy. No donor photos, remote content images, placeholders, blank media frames, or unrelated stock images.
- Do not render miniature decorative pictures anywhere. Footer media must be exactly zero: no `img`, `picture`, `svg`, `video`, `canvas`, `iframe`, or `source`.
- The street address may exist only in metadata and the single Google Maps embed on the contact page. It must never appear as visible text.
- Keep all seven taxonomies visible and internally linked through the homepage, header, footer, index pages, and detail pages without replacing NanoAvionics' editorial cadence with repetitive generic boxes.
- A release requires capture parity, content normalization, structural verification, the project compliance scan, full-resolution donor-versus-built review, desktop and mobile browser QA, clean nested-repository git proof, and live Vercel route and form verification.
